## 3. How we make decisions

- Members will discuss project-related decisions during weekly meetings.
- Everyone is encouraged to share opinions and suggestions.
- The group will try to reach an agreement before making important decisions.
- If an agreement cannot be reached, members will vote and the majority decision will be followed.
- Important decisions and task updates will be recorded in the group chat for future reference.

## 4. Meetings and communication

- The group will arrange two meeting in week to discuss progress, problems and upcoming tasks.
- WhatsApp will be used as the main communication channel.
- Members respond to group messages within 24 hours whenever possible.

## 5. Rules for Git and for code

- Every member works under their own name: `git config user.name` and `user.email` are set on every machine.
- Every member makes at least 3 commits of real work. Nobody commits for somebody else.
- Commit messages say what changed and why. Small commits are better than one big commit.
- Members should work on their own branches and push their completed work to the shared repository.
- Every pull request should be reviewed by at least one other member before merging into the main branch.
- No member should overwrite or delete another member's work without discussion.
- The original data files must remain unchanged.
- All members should run tests and check their code before submitting changes.

## 6. If someone does not contribute

- If a member does not complete their assigned work, the coordinator will send a friendly reminder and ask about the problem.
- If the problem continues, the group will inform the lecturer through email and provide relevant evidence.
- All contributions will be tracked through GitHub commit history, pull requests and completed tasks.
- Members understand that the lecturer may consider individual contributions and individual Q&A performance when determining marks.
